## 1. Применение и функционал <a id="component-purpose" name="component-purpose"></a>

Модуль `InspectorWindow` реализует окно инспектора объектов метаданных как всплывающее окно справа. Он управляет открытием, закрытием и обновлением окна инспектора в зависимости от выбора объекта в дереве метаданных.

**Основные функции**:
- Открытие окна инспектора при выборе объекта в дереве метаданных
- Загрузка данных формы инспектора через API
- Закрытие окна при смене/сбросе выбора
- Обновление имени окна при переименовании объекта
- Работа с правой боковой панелью через StateManager

## 2. Архитектура <a id="architecture" name="architecture"></a>

### Основные компоненты

```
InspectorWindow
    └─ Inspector (с правой боковой панелью)
```

### Используемые модули

- `StateManager` - управление глобальным состоянием приложения
- `$windows` - helper для управления окнами приложения
- `$api` - HTTP клиент для запросов к серверу
- `$message` - helper для отображения сообщений пользователю
- `Inspector` - компонент формы инспектора

### Идентификатор окна

```javascript
const INSPECTOR_WIN_ID = 'inspector-window:singleton';
```

Используется **один фиксированный** идентификатор окна инспектора. При каждом одиночном клике по узлу дерева метаданных `$windows.open(..., { uuid: INSPECTOR_WIN_ID })` перезаписывает содержимое уже открытого окна (через `WindowsCMP.openWindow`), а не создаёт новое. Тем самым в приложении существует **ровно одно** окно инспектора. Если окно было закрыто пользователем вручную, оно будет создано заново при следующем открытии узла.

### Инициализация

```javascript
componentDidMount() {
    StateManager.setState({ inspectorOnSave: this.onSave });
    StateManager.subscribeState({
        metadataSelected: { openInspector: this.onSelectedChange },
    });
    const sel = StateManager.state.metadataSelected;
    if (sel) this.onSelectedChange({ metadataSelected: sel });
}
```

При монтировании:
1. Регистрирует функцию `onSave` в глобальном состоянии
2. Подписывается на изменения выбора в дереве метаданных
3. Проверяет текущий выбор

### Обработка выбора узла (`onSelectedChange`)

Алгоритм работы:

1. Если выбор сброшен (`!metadataSelected`) → закрывает единственное окно инспектора
2. Извлекает `server`, `nodeKey` и `node` из выбранного объекта
3. Формирует URL для загрузки данных формы: `/{server}/{route}/metadata/{node.id}`
4. Запускает асинхронный запрос (старые ответы игнорируются через `_reqSeq`)
5. При получении данных открывает окно с компонентом `Inspector` через `$windows.open` с фиксированным `INSPECTOR_WIN_ID`. Если окно уже открыто — его содержимое перезаписывается; если закрыто — создаётся заново.

### Сохранение данных (`onSave`)

Функция `onSave` вызывается при нажатии кнопки "Сохранить" в инспекторе.

**Параметры**:
- `values` - объект со всеми значениями формы
- `afterSave` - функция, которую нужно вызвать после успешного сохранения
- `ctx` - контекст с `node`, `form` и опционально `server`

**Алгоритм**:
1. Извлекает `manifest.name` и `manifest.description` из значений
2. Формирует JSON-объект для отправки на сервер:
   - `owner_id` - идентификатор владельца (берётся напрямую из `node.ownerId`)
   - `class_id` - идентификатор класса
   - `class` - название класса
   - `name`, `description` - наименование и описание
   - `settings` - остальные поля формы
3. Отправляет запрос на сервер (PUT для update, POST для создания)
4. После успешного сохранения:
   - Вызывает `afterSave()` с новыми значениями
   - Обновляет состояние узла в StateManager
   - Переименовывает окно (если изменилось описание/имя)
   - Обновляет другие открытые окна редактирования
   - Показывает сообщение об успехе

## 3. Особенности применения <a id="apply-features" name="apply-features"></a>

### Ключевые особенности

1. **Всегда существует только одно окно инспектора** — при выборе нового объекта содержимое уже открытого окна перезаписывается (благодаря фиксированному `INSPECTOR_WIN_ID`); старое окно не остаётся висеть рядом
2. **Единый ID окна** — `inspector-window:singleton` (не зависит от `server`/`nodeKey`)
3. **Интеграция с TreeCMP/MetadataHier** - компонент реагирует на изменение `metadataSelected` в StateManager
4. **Поддержка ренейминга** - окно переименовывается при изменении имени/описания объекта
5. **Асинхронная загрузка** - данные загружаются по запросу, окно не открывается без данных

### Параметры окна

Окно открывается с параметрами:
```javascript
$windows.open(
    node.description || node.name,    // Заголовок
    <Inspector ... />,                // Контент
    { position: 'right', uuid: INSPECTOR_WIN_ID }  // Опции
);
```

Фиксированный `uuid` гарантирует, что в приложении существует только одно окно инспектора.

### Обновление формы

Форма инспектора автоматически обновляется при изменении объекта в дереве через подписку на `changeNode`:
- Слушает событие `changeNode` с уникальным именем
- При изменении объекта перезагружает данные через API
- Обновляет значения в форме
- Переименовывает окно при необходимости

### Очистка ресурсов

```javascript
componentWillUnmount() {
    StateManager.unsubscribeState({
        metadataSelected: ['openInspector'],
    });
    this._reqSeq++;
}
```

При размонтировании:
- Отписывается от событий StateManager
- Инкрементирует `_reqSeq` для отмены всех активных запросов

### Обработка ошибок

При ошибке загрузки данных:
- Выводится сообщение "Ошибка загрузки инспектора" через `$message`
- Состояние компонента сбрасывается (`currentNodeKey: null`, `currentServer: null`)
- Окно не открывается
