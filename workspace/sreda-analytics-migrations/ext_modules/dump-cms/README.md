# Документация модуля DumpDB

Модуль **DumpDB** предназначен для управления дампами базы данных, включая получение списка таблиц, создание дампов, восстановление данных из дампа и работу с метаданными загрузок.

---

## Структура модулей

Модуль имеет следующую структуру:

```
./services/DumpDB.service.js
./models/DumpBD.model.js
```

---

## Сервисный слой (DumpDBService)

Сервисный класс `DumpDBService` реализует основные операции по управлению дампом БД.

### Методы класса

#### 1. `GetTableList()`
Возвращает список всех таблиц в базе данных.

##### Параметры:
Нет параметров.

##### Возвращаемое значение:
Объект с информацией обо всех таблицах в базе данных.

---

#### 2. `Dump(params)`
Создает дамп таблицы с учетом фильтра.

##### Параметры:
- `params`: объект с двумя свойствами:
  - `table`: имя таблицы (необязательно; если не указано, возвращает пустой результат)
  - `where`: фильтр для выборки данных (опционально)

##### Возвращаемое значение:
Данные выбранной таблицы в формате массива объектов.

---

#### 3. `Restore(data)`
Восстанавливает данные из переданного дампа.

##### Параметры:
- `data`: объект с дампом данных для восстановления.

##### Возвращаемое значение:
- `{ result: true, msg: 'ok' }` – успешное восстановление
- `{ result: false, msg: error_message }` – ошибка восстановления с подробным сообщением об ошибке.

---

#### 4. `restoreFromStr(str)`
Восстанавливает базу данных из строки формата JSON.

##### Параметры:
- `str`: строка с JSON-данными дампа.

##### Возвращаемое значение:
- Результат восстановления аналогичен методу `Restore`.

---

#### 5. `restoreFromFile(filePath)`
Восстанавливает базу данных из файла дампа.

##### Параметры:
- `filePath`: путь к файлу с дампом.

##### Алгоритм метода:
1. Читает содержимое файла
2. Проверяет наличие такого дампа ранее через контрольную сумму MD5
3. Восстанавливает данные, если такой дамп еще не загружался
4. Сохраняет информацию о восстановлении в метаданных

##### Возвращаемое значение:
- `{ result: true, msg: 'Dump already loaded' }` – если дамп уже загружался раньше
- Результат восстановления аналогичен методу `Restore`.

---

#### 6. `restoreFromBuffer(name, buffer)`
Восстанавливает базу данных из буфера памяти.

##### Параметры:
- `name`: название дампа
- `buffer`: буфер с данными дампа

##### Алгоритм метода:
Аналогичен методу `restoreFromFile`, но работает непосредственно с буфером вместо файла.

##### Возвращаемое значение:
- Аналогично методу `restoreFromFile`.

---

#### 7. `checkMeta(hash)`
Проверяет существование метаданных загрузки дампа по заданному хешу.

##### Параметры:
- `hash`: контрольная сумма MD5 дампа.

##### Возвращаемое значение:
Логический флаг наличия метаданных.

---

#### 8. `setMeta(hash, name = '')`
Устанавливает метаданные о выполненной загрузке дампа.

##### Параметры:
- `hash`: контрольная сумма MD5 дампа
- `name`: необязательное имя дампа

##### Возвращаемое значение:
Результат сохранения метаданных.

---

## Использование модуля

Модуль предполагает использование совместно с моделью `DumpBD.model.js`, которая обеспечивает взаимодействие с базой данных и хранение метаданных загрузок.

Типичный сценарий использования включает:
1. Получение списка таблиц
2. Создание дампа нужной таблицы
3. Загрузка дампа обратно в систему из различных источников (файл, буфер, строка)
4. Контроль повторной загрузки одного и того же дампа через механизм проверки контрольных сумм.

---

## Примечания

- Все методы работают асинхронно и должны использоваться с ключевым словом `await`.
- Модуль активно использует транзакционный подход при восстановлении данных для обеспечения целостности базы данных.
- Для предотвращения повторного восстановления одинаковых дампов реализована проверка по контрольной сумме MD5.
