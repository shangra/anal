Документация для модуля управления ролями и разрешениями (RlsCore):

---

## Назначение модуля

Модуль предназначен для реализации механизма контроля доступа и управления правами пользователей на уровне таблиц базы данных. Модуль обеспечивает гибкость настройки разрешений через создание, удаление и проверку прав доступа различных типов пользователей (группы, роли, индивидуальные пользователи).

---

## Основные компоненты модуля

### Класс RlsCoreService

Класс наследуется от базового класса расширений `Extensions` и реализует основные методы для управления разрешениями.

#### Методы класса

1. **transactional(_, functionParams, source)** *(декорируемый метод)*  
   Обеспечивает транзакционную обработку методов класса.
   
2. **addPermissions(table_name, idsForCreating, type, owner, owner_id, transaction)**  
   Добавляет разрешения для указанных записей таблицы.
   
3. **delAllPermissions(table_name, transaction)**  
   Полностью очищает все разрешения для заданной таблицы.
   
4. **delPermissions(table_name, table_ids, type, owner, owner_id, transaction)**  
   Удаляет конкретные разрешения для выбранных записей таблицы.
   
5. **getPermissions(table_name, table_id, owner, type, owner_id, transaction)**  
   Возвращает текущие разрешения для указанного элемента таблицы.
   
6. **getChildrenNested(table_name, table_id, transaction)**  
   Получает вложенные элементы иерархической структуры для выбранной записи.
   
7. **addPermissionNested(table_name, table_id, type, owner, owner_id, transaction)**  
   Устанавливает разрешение на запись с учетом иерархических связей.
   
8. **delPermissionNested(table_name, table_id, type, owner, owner_id, transaction)**  
   Удаляет разрешение на запись с учетом иерархических связей.
   
9. **addParentPermissionsNested(parentId, childId, table_name, options, transaction)**  
   Создает родительские разрешения для дочерних объектов.
   
10. **delParentPermissionsNested(parentId, childId, table_name, transaction)**  
    Удаляет родительские разрешения для дочернего объекта.
    
11. **getAccessUser()**  
    Возвращает информацию об авторизованном пользователе (его группы, роли и права).
    
12. **setUserPermissions(table_name, table_id, types, permissions, transaction)**  
    Устанавливает комплекс разрешений для пользователя на указанную таблицу.
    
13. **getAccessStatus(table_name, table_id, transaction)**  
    Проверяет текущий статус доступа пользователя к элементу таблицы (чтение, изменение, просмотр, удаление).
    
14. **delPermissionsByTableId(table_name, table_id, options?)**  
    Удаляет все разрешения для указанной записи таблицы.
    
15. **delPermissionsByType(table_name, table_id, type, options?)**  
    Удаляет разрешения определенного типа для записи таблицы.
    
16. **delPermissionsByTypeAndOwner(table_name, table_id, type, owner, options?)**  
    Удаляет разрешения определенного типа и владельца для записи таблицы.
    
17. **checkAccessWrite(table_name, table_id, transaction)**  
    Проверяет наличие прав на изменение записи.
    
18. **checkAccessView(table_name, table_id, transaction)**  
    Проверяет наличие прав просмотра записи.
    
19. **checkAccessRead(table_name, table_id, transaction)**  
    Проверяет наличие прав чтения записи.
    
20. **checkAccessDelete(table_name, table_id, transaction)**  
    Проверяет наличие прав удаления записи.
    
21. **getAccessStatusMulti(table_name, ids, transaction)**  
    Массовый запрос статуса доступа для множества записей.

## Использование модуля

Модуль интегрируется в систему через стандартный механизм расширения ядра платформы NodeCMS. Для интеграции достаточно указать модуль в зависимостях пакета (`package.json`) и настроить необходимые роуты и сервисы.

Типичный сценарий использования включает:

- Настройку разрешений при создании новых записей
- Проведение проверок доступа перед выполнением критичных операций (редактирование, удаление)
- Интеграцию с существующими сервисами аутентификации и авторизации

---

## Пример использования метода проверки доступа

```javascript
try {
    // проверяем право на чтение записи с ID=123 в таблице users
    await rlsService.checkAccessRead('users', 123, currentTransaction);
    
    // продолжаем выполнение операции...
} catch(error) {
    console.error('Ошибка доступа:', error.message);
}
```

## Заключение

Модуль RlsCore представляет собой мощный инструмент для централизованного управления разрешениями и контролем доступа в приложениях на платформе NodeCMS. Гибкая система настроек и встроенные механизмы проверки позволяют эффективно защищать данные и обеспечивать безопасность приложений.

# Документация для модуля RlsCoreService

RlsCoreService представляет собой сервис управления правами доступа (Role-Based Access Control, RBAC) в приложении. Данный модуль предназначен для обработки и контроля разрешений пользователей на выполнение различных операций над объектами базы данных.

## Основные Функции Модуля

### 1. Управление транзакциями
Метод **transactional** обеспечивает управление транзакциями баз данных. Позволяет выполнять запросы атомарно, обеспечивая целостность данных.

#### Пример использования:
```javascript
await service.transactional(async (serviceInstance, args) => {
    await serviceInstance.someMethod(args);
}, { someParam: value });
```

---

### 2. Добавление Прав Доступа
Метод **addPermissions** добавляет разрешения пользователям или группам на определенные таблицы и записи.

#### Параметры метода:
- **table_name**: имя таблицы
- **idsForCreating**: массив ID записей
- **type**: тип разрешения ('view', 'read', 'write' или 'delete')
- **owner**: владелец разрешения ('group', 'role' или 'ruleLog')
- **owner_id**: идентификатор владельца

---

### 3. Удаление Прав Доступа
Методы удаления прав доступа позволяют удалять существующие разрешения:
- **delAllPermissions**: полное удаление всех разрешений для определенной таблицы
- **delPermissions**: удаление выбранных разрешений по таблице, типу и владельцу

---

### 4. Проверка Разрешений
Методы проверки прав доступа проверяют наличие определенных разрешений перед выполнением операций:
- **checkAccessWrite**, **checkAccessView**, **checkAccessRead**, **checkAccessDelete**: проверка наличия соответствующего типа разрешения

---

### 5. Работа с Вложенными Элементами
Методы **getChildrenNested**, **addPermissionNested**, **delPermissionNested** обеспечивают работу с иерархическими структурами данных, позволяя добавлять или удалять разрешения рекурсивно для родительских объектов и их потомков.

---

### 6. Копирование Прав Родителя
Методы **addParentPermissionsNested** и **delParentPermissionsNested** предназначены для автоматического наследования разрешений от родительского объекта к дочерним объектам.

---

### 7. Статус Доступа Пользователей
Метод **getAccessUser** возвращает текущие группы, роли и правила текущего пользователя.

Метод **getAccessStatus** проверяет текущий статус разрешений пользователя для определенного объекта.

---

### 8. Вспомогательные Методы
- **setUserPermissions**: установка набора разрешений для пользователя
- **getAccessStatusMulti**: массовая проверка статуса разрешений для множества объектов

---

## Дополнительные Особенности

- Поддерживается работа с транзакциями через параметр `transaction`
- Реализована система отображений имен таблиц через свойство `mapping`
- Используются встроенные механизмы ошибок приложения через класс `ApiError`

---

Данный модуль интегрируется в общую архитектуру приложения через стандартный подход, описанный в документации проекта, где сервисы подключаются контроллерами, а контроллеры маршрутизируются через роуты.
