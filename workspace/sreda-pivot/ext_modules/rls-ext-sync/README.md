# Документация модуля RlsExtSyncService

Данный модуль предназначен для синхронизации правил уровня строк (RLS — Row Level Security) с таблицами базы данных. Он обеспечивает автоматическое создание и удаление представлений (views), а также управление разрешениями доступа к данным на уровне строк.

## Основные задачи модуля:

1. **Синхронизация RLS после изменений** (`syncAfter`) – автоматически обновляет правила RLS при изменении таблицы.
   
2. **Очистка RLS перед изменениями** (`dropBefore`) – очищает существующие правила RLS до внесения изменений.

3. **Добавление полей формы** (`formAfter`) – добавляет поле для включения RLS в форму редактирования таблицы.

4. **Чтение параметров перед запросом** (`readBefore`) – устанавливает параметры запроса, такие как наличие RLS и имя таблицы.

5. **Управление представлениями и правилами RLS** – создает и удаляет представления, управляет правами доступа к данным.

---

## Методы класса RlsExtSyncService

### Конструктор
Класс наследуется от базового класса расширений (`Extensions`), который предоставляет доступ к системным функциям платформы.

### Метод `dropBefore`
Выполняется перед изменением таблицы. Очищает текущие настройки RLS и возвращает результат выполнения основной функции.

### Метод `syncAfter`
Запускается после изменения таблицы. Синхронизирует правила RLS с текущей структурой таблицы.

### Метод `formAfter`
Добавляет в форму управления таблицей поле для активации RLS.

### Метод `readBefore`
Устанавливает дополнительные параметры запроса, включая информацию о наличии RLS и имени таблицы.

### Приватные вспомогательные методы

#### `getRlsAndTable`
Возвращает конфигурацию RLS и название таблицы из кеша или загружает её из хранилища метаданных.

#### `drop`
Удаляет представление и очищают правила RLS для указанной таблицы.

#### `sync`
Создает новое представление и применяет новые правила RLS, если они активированы.

#### `clearRls`
Полностью удаляет все права доступа для данной таблицы.

#### `addRls`
Рекурсивно добавляет права доступа для всех записей таблицы.

#### `recursiveAddRls`
Использует рекурсию для добавления прав доступа порциями, чтобы избежать перегрузки базы данных большими объемами данных.

#### `getConnect`
Получает соединение с базой данных через указанный коннектор.

#### `dropView`
Удаляет существующее представление для таблицы.

#### `createView`
Создаёт новое представление, включающее иерархию потомков и предков объектов.

#### `isRlsOn`
Проверяет, включена ли настройка RLS для данной таблицы.

## Использование модуля

Модуль интегрируется в систему через механизм расширений и вызывается автоматически при соответствующих событиях (изменении таблицы). Для его работы необходимо настроить подключение к базе данных и указать таблицу, для которой будут применяться правила RLS.

---

## Примечания

- Модуль использует кеширование для ускорения получения настроек RLS и названия таблицы.
- При добавлении новых записей в базу данных происходит асинхронное обновление правил RLS.
- Представления создаются динамически и могут использоваться для отображения дополнительных атрибутов объектов.

---

Этот модуль является важным компонентом обеспечения безопасности и контроля доступа к данным на уровне отдельных строк в базе данных.
