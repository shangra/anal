# Документация модуля SchemasManager

Данный модуль предназначен для управления схемами (schemas) в системе. Модуль включает в себя функциональность для создания, чтения, обновления и удаления схем, а также управление разрешениями доступа к этим схемам.

---

## Основные компоненты модуля

### Класс SchemaService

Класс `SchemaService` наследуется от базового класса `Extensions` и реализует основные методы для работы со схемами.

---

## Методы класса SchemaService

### 1. getAllSchemas(ownerId)
Возвращает все схемы принадлежащие владельцу.

**Параметры:**
- `ownerId`: ID владельца схем

**Возвращаемое значение:** массив метаданных всех схем владельца

---

### 2. getSchema(ownerId, schemaId)
Получает информацию о конкретной схеме.

**Параметры:**
- `ownerId`: ID владельца схемы
- `schemaId`: ID запрашиваемой схемы

**Возвращаемое значение:** метаданные запрошенной схемы

---

### 3. editSchema(ownerId, schemaId, shemaInfo, schema, snapshot)
Редактирует существующую схему.

**Параметры:**
- `ownerId`: ID владельца схемы
- `schemaId`: ID редактируемой схемы
- `shemaInfo`: информация о схеме (объект с полями name, forAll, standart)
- `schema`: схема (опционально)
- `snapshot`: снимок состояния схемы (опционально)

**Возвращаемое значение:** обновленные метаданные схемы

---

### 4. createSchema(ownerId, shemaInfo, schema, snapshot, userId)
Создает новую схему.

**Параметры:**
- `ownerId`: ID владельца новой схемы
- `shemaInfo`: информация о создаваемой схеме (объект с полями name, forAll, standart)
- `schema`: схема (опционально)
- `snapshot`: снимок состояния схемы (опционально)
- `userId`: ID пользователя создающего схему (опционально)

**Возвращаемое значение:** метаданные созданной схемы

---

### 5. delSchema(ownerId, schemaId)
Удаляет существующую схему.

**Параметры:**
- `ownerId`: ID владельца схемы
- `schemaId`: ID удаляемой схемы

**Возвращаемое значение:** результат удаления

---

### 6. deleleAllPermission(schemaId, user_id)
Удаляет все разрешения для пользователя на конкретную схему.

**Параметры:**
- `schemaId`: ID схемы
- `user_id`: ID пользователя

---

### 7. createPermissionRules(schemaId, rules_id)
Создает правила разрешений для схемы.

**Параметры:**
- `schemaId`: ID схемы
- `rules_id`: ID набора правил

---

### 8. delPermissionRules(schemaId, rules_id)
Удаляет правила разрешений для схемы.

**Параметры:**
- `schemaId`: ID схемы
- `rules_id`: ID набора правил

---

### 9. createPermissionReadAll(schemaId)
Создает разрешение на чтение для всех пользователей.

**Параметр:**
- `schemaId`: ID схемы

---

### 10. delPermissionReadAll(schemaId)
Удаляет разрешение на чтение для всех пользователей.

**Параметр:**
- `schemaId`: ID схемы

---

### 11. createPermissionAdministrator(schemaId)
Создает административное разрешение для схемы.

**Параметр:**
- `schemaId`: ID схемы

---

### 12. createPermissions(schemaId, user_id, typePermission)
Создает разрешения для пользователя на схему.

**Параметры:**
- `schemaId`: ID схемы
- `user_id`: ID пользователя
- `typePermission`: тип разрешения ('read' или 'write')

---

### 13. setPermissions(ownerId, schemaId, user_id, typePermission)
Устанавливает разрешения для пользователя на схему.

**Параметры:**
- `ownerId`: ID владельца схемы
- `schemaId`: ID схемы
- `user_id`: ID пользователя
- `typePermission`: тип разрешения ('read' или 'write')

**Возвращаемое значение:** объект результата установки разрешений

---

### 14. delPermissions(ownerId, schemaId, user_id)
Удаляет разрешения для пользователя на схему.

**Параметры:**
- `ownerId`: ID владельца схемы
- `schemaId`: ID схемы
- `user_id`: ID пользователя

**Возвращаемое значение:** объект результата удаления разрешений

---

## Зависимости

Модуль зависит от следующих компонентов:
- `httpContext`: сервис HTTP-контекста
- `Extensions`: базовый класс расширений
- `ServiceClass`: сервис метаданных
- `RlsCoreServiceClass`: сервис управления правами доступа

---

## Примечания

1. Все методы обработки схем работают асинхронно
2. Управление разрешениями реализовано через систему прав доступа (RLS)
3. Для некоторых методов проверяется право текущего пользователя на выполнение операции
