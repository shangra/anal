# Документация модуля Fields

## Обзор

Модуль **Fields** предназначен для управления полями метаданных в системе. Он расширяет функциональность базового класса `DefaultMetaObject` из пакета `metadata-cmp`. Модуль предоставляет форму конфигурации полей с различными типами атрибутов, такими как имя поля, тип данных, длина, точность и дополнительные настройки.

---

## Структура модуля

Модуль имеет следующую внутреннюю структуру:

```bash
./fields/
├── services/
│   └── Fields.service.js
├── controllers/
│   └── Fields.controller.js
├── routers/
│   └── Fields.router.js
├── __tests__/
│   └── tests/
│       └── Fields.service.test.js
└── package.json
```

---

## Основные компоненты

### 1. Service Layer (`Fields.service.js`)

Класс `GuideFieldsService` наследуется от `DefaultMetaObject` и переопределяет метод `form()` для предоставления формы конфигурации полей.

#### Ключевые свойства:

- `id`: Уникальный идентификатор компонента
- `component`: Имя компонента ("Fields")

#### Метод `form(id)`
Возвращает конфигурационную форму для создания и редактирования полей метаданных. Форма включает следующие элементы:

- `nameField`: Имя поля в СУБД (строка)
- `type`: Тип поля (список возможных типов)
- `length`: Длина поля (целое число)
- `precision`: Точность (целое число)
- `increment`: Автоинкремент (булево значение)
- `notnull`: Обязательность заполнения (булево значение)
- `unique`: Уникальность значения (булево значение)
- `showfield`: Показывать поле (булево значение, по умолчанию `true`)
- `editing`: Возможность редактирования (булево значение, по умолчанию `true`)
- `ref`: Ссылка (ссылочный тип атрибута)

---

### 2. Controller Layer (`Fields.controller.js`)

Контроллер обрабатывает HTTP-запросы и взаимодействует с сервисным слоем. Ожидается наличие стандартных методов CRUD:

- GET `/fields/:id` — получение информации о конкретном поле
- POST `/fields` — создание нового поля
- PUT `/fields/:id` — обновление существующего поля
- DELETE `/fields/:id` — удаление поля

Каждый метод должен содержать обязательную строку описания в `res.locals.description` для целей мониторинга и логирования.

---

### 3. Router Layer (`Fields.router.js`)

Маршрутизатор настраивает конечные точки API для взаимодействия с модулем через HTTP-протокол. Пример маршрутизации:

```javascript
router.route('/fields')
    .get(FieldsController.getAll)
    .post(FieldsController.create);

router.route('/fields/:id')
    .get(FieldsController.getById)
    .put(FieldsController.update)
    .delete(FieldsController.remove);
```

---

### 4. Тестирование (`Fields.service.test.js`)

Тестовый файл проверяет работу основных методов сервиса. Например:

```javascript
test('Test form method returns correct structure', () => {
    const fieldsService = new GuideFieldsService();
    const formStructure = fieldsService.form(1);
    
    expect(formStructure.form.length).toEqual(10); // Проверка количества элементов формы
});
```

# Документация для модуля FieldsList

## Описание модуля

Модуль **FieldsList** предназначен для управления списком полей в системе. Этот модуль расширяет функциональность базового класса `DefaultMetaObject` из пакета `metadata-cmp`. Основная цель модуля – предоставление интерфейса для формирования списка полей, используемых в различных компонентах системы.

---

## Структура модуля

### Папки и файлы

- **services**: содержит основные сервисы модуля
  - `FieldsList.service.js`: основной сервис для работы со списком полей
  - `Fields.service.js`: сервис для работы с полями
  - `SysFields.service.js`: сервис для работы с системными полями

- **package.json**: конфигурационный файл модуля

---

## Сервис FieldsListService

Сервис `FieldsListService` наследуется от базового класса `DefaultMetaObject` и переопределяет необходимые свойства и методы.

### Конструктор

Конструктор инициализирует базовые параметры сервиса:

- `super(__dirname)` – передает директорию текущего файла родительскому классу
- Устанавливает имя сервиса `'FieldsList'`
- Присваивает значения свойствам `id` и `component` из констант, определенных в отдельном файле `constants`

### Метод form()

Метод возвращает форму конфигурации поля, которая включает следующее определение:

```javascript
return {
    form: [
        {
            name: 'ref',
            description: 'Поле',
            type: 'GREF',
            link: {
                type: 'local', // тип ссылки: local, global, single
                metalink: [new FieldsService().id, new SysFieldsService().id], // массив ссылок на сервисы полей
            },
        },
    ],
};
```

Где:
- `name`: название поля ('ref')
- `description`: описание поля ('Поле')
- `type`: тип поля ('GREF' – вероятно Generic Reference)
- `link`: объект, определяющий связь поля
  - `type`: тип связи ('local')
  - `metalink`: массив ID сервисов, связанных с полем

---

## Использование модуля

Для использования функционала модуля необходимо создать экземпляр сервиса `FieldsListService` и вызвать метод `form()` для получения формы конфигурации поля:

```javascript
const FieldsListService = require('./services/FieldsList.service');
const fieldsListService = new FieldsListService();

fieldsListService.form().then(formConfig => {
    console.log(formConfig); // вывод конфигурации формы
}).catch(error => {
    console.error('Ошибка при получении формы:', error);
});
```

# Документация для модуля Forms

## Обзор

Модуль **Forms** предназначен для управления формами в системе. Он наследуется от класса `DefaultMetaObject` и расширяет его функциональность специфичными методами для создания, чтения, обновления и удаления форм. Модуль интегрируется с другими сервисами через использование классов `PagesUiService` и `TemplatesService`, обеспечивая взаимодействие с страницами и шаблонами соответственно.

---

## Структура модуля

Модуль состоит из одного основного файла:

- `forms.service.js`: Основной файл сервиса, содержащий класс `FormsService`.

---

## Класс FormsService

Класс `FormsService` реализует основные методы для работы с формами.

### Конструктор

Конструктор инициализирует базовые параметры формы:

- `this.id`: Уникальный идентификатор формы.
- `this.component`: Компонент, связанный с формой.

```javascript
constructor() {
    super(__dirname);
    const name = 'Forms';
    this.id = constants[name].id;
    this.component = constants[name].component;
}
```

---

### Методы

#### form()
Возвращает конфигурацию интерфейса формы, включающую несколько вкладок с различными настройками:

- **Основное**: Настройки основной информации формы.
- **Шаблон формы**: Код шаблона формы.
- **Код на клиенте**: Клиентский код формы.
- **Код на сервере**: Серверный код формы.

```javascript
async form() {
    return {
        form: [...]
    };
}
```

#### create(body)
Метод для создания новой формы. Логика реализации пока отсутствует.

```javascript
async create(body) {
    console.log('create', body);
}
```

#### read(id, options)
Метод для чтения существующей формы по её идентификатору. Поддерживает дополнительные опции.

```javascript
async read(id, options = {}) {
    console.log('read', id, options);
}
```

#### update(id, body)
Метод для обновления существующей формы. Требует передачи идентификатора формы и нового состояния.

```javascript
async update(id, body) {
    console.log('update', id, body);
}
```

#### delete(id)
Метод для удаления формы по её идентификатору.

```javascript
async delete(id) {
    console.log('delete', id);
}
```

Модуль интегрируется с остальными частями системы через использование следующих сервисов:

- **PagesUiService**: Сервис для взаимодействия с UI страницами.
- **TemplatesService**: Сервис для работы с шаблонами.

Эти сервисы импортируются и используются для расширения функциональности модуля.

# Документация модуля GuideService

## Описание модуля

Модуль **GuideService** предназначен для управления метаданными справочников в системе. Он наследуется от класса `DefaultMetaObject` и расширяет его функциональность специфическими методами для работы со справочниками. Модуль обеспечивает создание, чтение, обновление и удаление метаданных справочников, а также управление формами и полями справочников.

---

## Основные компоненты модуля

### Класс GuideService

Класс `GuideService` реализует основные методы для работы с метаданными справочников. Ключевые свойства и методы описаны ниже.

#### Свойства

- `id`: Уникальный идентификатор справочника.
- `component`: Компонент справочника.

#### Методы

1. ### `async form(id)`
   
   Метод возвращает конфигурацию формы справочника.

   #### Параметры
   - `id`: Идентификатор справочника.

   #### Возврат
   Конфигурация формы справочника в формате объекта.

2. ### `async #isParentForm(id)`
   
   Внутренний метод проверки, является ли форма родительской.

   #### Параметры
   - `id`: Идентификатор справочника.

   #### Возврат
   Логический результат проверки (`true` или `false`).

3. ### `getFormFields(isParentForm)`
   
   Метод возвращает поля формы справочника.

   #### Параметры
   - `isParentForm`: Флаг, указывающий, является ли форма родительской.

   #### Возврат
   Список полей формы справочника.

4. ### `async createMetadata(body)`
   
   Создает метаданные справочника и добавляет базовые поля.

   #### Параметры
   - `body`: Тело запроса с настройками справочника.

   #### Возврат
   Созданный справочник.

5. ### `async create(id, body, options)`
   
   Создает новый элемент справочника.

   #### Параметры
   - `id`: Идентификатор справочника.
   - `body`: Тело запроса с данными элемента.
   - `options`: Дополнительные опции.

   #### Возврат
   Созданный элемент справочника.

6. ### `async read(id, options)`
   
   Читает элемент справочника.

   #### Параметры
   - `id`: Идентификатор элемента справочника.
   - `options`: Дополнительные опции.

   #### Возврат
   Элемент справочника.

7. ### `async update(id, body)`
   
   Обновляет элемент справочника.

   #### Параметры
   - `id`: Идентификатор элемента справочника.
   - `body`: Тело запроса с обновленными данными.

   #### Возврат
   Обновленный элемент справочника.

8. ### `async delete(id, body)`
   
   Удаляет элемент справочника.

   #### Параметры
   - `id`: Идентификатор элемента справочника.
   - `body`: Тело запроса с дополнительными данными.

   #### Возврат
   Результат удаления.

9. ### `async updateMetadata(id, body, transaction)`
   
   Обновляет метаданные справочника.

   #### Параметры
   - `id`: Идентификатор справочника.
   - `body`: Тело запроса с новыми метаданными.
   - `transaction`: Транзакция базы данных.

   #### Возврат
   Обновленные метаданные справочника.

---

## Зависимости

Модуль зависит от следующих компонентов:

- `DefaultMetaObject`: Базовый класс для работы с метаданными.

# Документация для модуля Indexes

## Сервисный класс `IndexesService`

Сервисный класс `IndexesService` наследуется от базового класса `DefaultMetaObject`, обеспечивая стандартизированное управление объектами индексации.


#### Важные моменты:

# Документация модуля Keys

## Обзор

Модуль **Keys** предназначен для управления ключами объектов в системе. Он наследуется от класса `DefaultMetaObject` и расширяет его функциональность специфическими полями и методами, необходимыми для работы с ключами.

## Структура модуля

Модуль состоит из одного файла:

- `services/Keys.service.js`: основной сервис, содержащий всю логику работы с ключами.

## Основные компоненты

### Класс KeysService

Класс `KeysService` наследует класс `DefaultMetaObject` и добавляет дополнительную конфигурацию полей формы для ключей.

#### Конструктор

Конструктор инициализирует базовые свойства ключа:

- `this.id`: уникальный идентификатор компонента
- `this.component`: имя компонента ("Keys")

#### Метод form()

Метод возвращает конфигурацию формы для создания и редактирования ключей. Форма включает три основных поля:

1. **Primary Key**:
   - Имя: `primarykey`
   - Описание: Первичный ключ
   - Тип: `BOOL` (логический тип)
   
2. **Field View**:
   - Имя: `fieldview`
   - Описание: Поле представления
   - Тип: `REF` (ссылочный тип)
   - Связь: локальная связь с компонентами `Fields` и `SysFields`
   
3. **Template View**:
   - Имя: `templateview`
   - Описание: Шаблон представления
   - Тип: `STRING` (строка)
   - Значение по умолчанию: шаблон `'[[field1]] ([[field2]] - [[field3]])'`

## Использование

Модуль предназначен для интеграции в систему через стандартный механизм загрузки сервисов. Для использования функционала модуля достаточно создать экземпляр класса `KeysService` и вызвать необходимые методы.

Пример использования:

```javascript
const KeysService = require('./services/Keys.service');
const keysService = new KeysService();

// Получить форму конфигурации ключей
const formConfig = keysService.form();
console.log(formConfig);
```

## Интеграция с системой

Модуль интегрируется в общую архитектуру системы как часть метаданных компонентов. Через наследование от базового класса `DefaultMetaObject` модуль получает доступ ко всей инфраструктуре платформы, включая механизмы расширения и взаимодействия с другими компонентами.

## Особенности реализации

Ключевой особенностью реализации является использование ссылочного типа `REF` для поля `fieldview`, которое связывает ключ с полем представления. Это позволяет гибко настраивать представление ключей в зависимости от связанных сущностей.

Также стоит отметить использование механизма шаблонов для поля `templateview`, что обеспечивает возможность кастомизации отображения ключей в различных сценариях использования.

# Документация для модуля Tabular Parts Service

## Обзор

Модуль **Tabular Parts Service** предназначен для управления табличными частями в системе. Табличные части представляют собой наборы связанных записей, организованных в виде таблиц. Данный сервис обеспечивает создание, чтение, обновление и удаление этих табличных частей, а также управление метаданными полей, связанными с ними.

---

## Структура Модуля

### Основные компоненты:

1. **Метаданные:** Управление структурой и настройками табличных частей через классы и сервисы метаданных.
   
2. **CRUD Операции:** Реализация базовых операций над табличными частями: создание, чтение, обновление и удаление.

3. **Связи:** Поддержка связей между различными табличными частями, например, ведение ведущей табличной части.

---

## Ключевые Функции

### Методы Сервисов

#### 1. Формирование формы (`form`)
Возвращает конфигурацию формы для отображения и ввода данных табличной части.

**Параметры**: Нет  
**Возврат**: Конфигурация формы в виде массива объектов.

_Пример результата:_
```json
[
    {
        "name": "table",
        "description": "Имя таблицы",
        "type": "STRING",
        "template": "test_table"
    },
    ...
]
```

---

#### 2. Создание метаданных (`createMetadata`)
Создает новую запись метаданных для табличной части и автоматически добавляет необходимые системные поля.

**Параметры**:  
- `body`: тело запроса с информацией о создаваемой табличной части.

**Возврат**: Созданную таблицу с настроенными полями.

---

#### 3. Обновление метаданных (`updateMetadata`)
Обновляет существующую запись метаданных табличной части и управляет связью с ведущими табличными частями.

**Параметры**:  
- `body`: обновленные данные.
- `transaction`: транзакционный контекст (если применимо).

**Возврат**: Обновленную информацию о таблице.

---

#### 4. Базовые CRUD операции

Эти методы делегируют выполнение операций непосредственно классу `TableMetadata`:

- `create(id, tabular, body)` — создает новую запись в табличной части.
- `read(id, tabular, options={})` — читает существующие записи.
- `update(id, tabular, body)` — обновляет выбранную запись.
- `delete(id, tabular, body)` — удаляет указанную запись.

---

## Связь с Ведущими Табличными Частями

Сервис поддерживает автоматическую обработку связи с ведущей табличной частью:

- Автоматически добавляет поле `ownerTabularPart` при наличии ссылки на ведущую часть.
- Убирает данное поле, когда связь разрывается.

---

## Использование Классов Метаданных

Модуль активно взаимодействует с классами метаданных:

- `TabularPartsClass`: Класс для работы с самим объектом табличной части.
- `FieldsServiceClass`: Используется для управления полями, связанными с табличной частью.
