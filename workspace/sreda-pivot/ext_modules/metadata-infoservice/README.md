# Документация для модуля Fields

## Описание модуля

Модуль **Fields** предназначен для управления полями метаданных в системе. Он наследуется от класса `DefaultMetaObject` и расширяет его функциональность специфичными настройками полей. Модуль предоставляет форму конфигурации полей с различными типами атрибутов, такими как имя поля, тип данных, длина, поддержка внешних ключей и ссылок, виртуальные поля и т.д.

## Основные компоненты модуля

### Класс FieldsService

Класс `FieldsService` реализует основную логику обработки полей метаданных. Он наследует базовый класс `DefaultMetaObject` и переопределяет метод `form()` для предоставления формы настройки полей.

#### Атрибуты класса

- `id`: Уникальный идентификатор компонента `"1fa330a3-4b65-42e4-b12f-1fabd0c08945"`
- `component`: Имя компонента `"Fields"`

#### Метод form()

Метод возвращает конфигурационную форму для создания и редактирования полей метаданных. Форма состоит из массива объектов, каждый из которых представляет отдельное поле с его настройками.

Конфигурационная форма включает следующие типы полей:

1. Базовая информация о поле:
   - `nameField` (строка): Имя поля в СУБД
   - `type` (список): Тип поля (uuid, text, string, integer, float, date, datetime, boolean, json, ref)
   - `length` (целое число): Длина поля (по умолчанию шаблонное значение "255")

2. Настройки виртуальных полей:
   - `virtual` (булево): Является ли поле виртуальным
   - `calculated` (булево): Является ли виртуальное поле вычисляемым
   - `fnfield` (текст): Значение виртуального поля (шаблонное значение "CONCAT(\"field2\", \"field2\")")

3. Поддержка иерархических структур:
   - `hierarchy` (булево): Поддерживает ли поле иерархию
   - `subtotal` (булево): Используются ли промежуточные итоги иерархии

4. Внешние ключи и ссылки:
   - `foreignkey` (ссылка): Внешний ключ с возможностью выбора типа связи (local, global, single)
   - `ref` (глобальная ссылка): Ссылка на другой компонент
   - `refOrderField` (родительская ссылка): Поле сортировки по ссылке
   - `refOrderDirection` (список): Направление сортировки (ASC/DESC)

5. Дополнительные настройки:
   - `isOrderOn` (булево): Активирована ли сортировка
   - `SQLQueryFormat` (список): Формат соединения SQL-запросов (виртуальное соединение, соединение в СУБД, денормализованное соединение)
   - `onoff` (булево): Включено/выключено поле

## Использование модуля

Модуль `Fields` интегрируется в систему через стандартный механизм модулей платформы. Для интеграции необходимо:

1. Создать пакетный файл `package.json` с указанием зависимости от ядра системы
2. Разместить модуль в структуре директорий согласно архитектуре проекта
3. Подключить сервис модуля в контроллере и маршрутизаторе
4. Использовать метод `form()` для получения конфигурации формы полей

## Пример использования

```javascript
const FieldsService = require('./services/Fields.service');
const fieldsService = new FieldsService();

async function createFieldConfig() {
    try {
        const configForm = await fieldsService.form();
        console.log(configForm); // Выведет полную конфигурацию формы
        
        // Пример использования полученной конфигурации для создания нового поля
        const newFieldData = {
            nameField: 'new_field_name',
            type: 'string',
            length: 100,
            virtual: false,
            calculated: false,
            hierarchy: false,
            subtotal: false,
            foreignkey: null,
            ref: null,
            refOrderField: null,
            refOrderDirection: 'ASC',
            isOrderOn: true,
            SQLQueryFormat: 'useWith',
            onoff: false
        };
        
        // Логика сохранения новой конфигурации поля...
    } catch (error) {
        console.error('Ошибка при создании конфигурации поля:', error);
    }
}

createFieldConfig();
```

## Заключение

Модуль **Fields** предоставляет мощный инструментарий для управления полями метаданных в системе. Его гибкая конфигурация позволяет адаптироваться под различные требования проектов, обеспечивая поддержку широкого спектра типов данных и сложных связей между ними.

# Документация для модуля FieldsList

## Обзор
Модуль **FieldsList** предназначен для управления списком полей, используемых в различных компонентах системы. Модуль построен на основе базовой службы метаданных `DefaultMetaObject.service` и расширяет её функциональность специфическими методами для работы со списком полей.

---

## Структура модулей

Модуль имеет следующую внутреннюю структуру:

```
./fields-list/
├── services/
│   └── FieldsList.service.js
└── package.json
```

---

## Основные компоненты

### 1. Класс `FieldsListService`
Класс наследуется от базового класса `DefaultMetaObject.service` и добавляет специализированную функциональность для работы со списком полей.

#### Конструктор
Конструктор инициализирует базовые свойства родительского класса и устанавливает уникальные параметры текущего модуля:

- `this.id`: Уникальный идентификатор модуля `"52a9e785-f68e-4427-b246-135620eea36f"`
- `this.component`: Имя компонента `"FieldsList"`

#### Метод `form()`
Метод возвращает конфигурацию формы списка полей. Возвращаемый объект содержит массив объектов-полей, каждый из которых включает:

- `name`: имя поля
- `description`: описание назначения поля
- `type`: тип поля ("REF")
- `link`: ссылка на уникальный идентификатор связанной службы
- `class`: класс связанной службы

Возвращаемое значение метода выглядит примерно так:

```javascript
{
    form: [
        {
            name: 'ref',
            description: 'Поле',
            type: 'REF',
            link: '<идентификатор_связанной_службы>',
            class: FieldsService
        }
    ]
}
```

---

## Интеграция с другими компонентами

Модуль активно взаимодействует с двумя основными службами:

1. **DefaultMetaObject.service**: Базовая служба метаданных, обеспечивающая общие механизмы работы с объектами.
   
2. **Fields.service**: Служба, ответственная непосредственно за работу с полями. Используется через ссылку и класс в конфигурации формы.

---

## Использование

Модуль предназначен для интеграции в систему управления контентом и метаданными. Типичное использование предполагает создание экземпляров класса `FieldsListService` и вызов методов для формирования интерфейсов администрирования и настройки полей компонентов.

Пример создания экземпляра и получения конфигурации формы:

```javascript
const fieldsListService = new FieldsListService();
const formConfig = await fieldsListService.form();
console.log(formConfig); // вывод конфигурации формы
```

---

## Особенности реализации

- Наследование базовых механизмов от `DefaultMetaObject.service` обеспечивает совместимость с общей архитектурой платформы.
- Специфическая реализация метода `form()` позволяет гибко настраивать интерфейс взаимодействия с полем.
- Использование уникальных идентификаторов и ссылок на классы других сервисов обеспечивает модульность и масштабируемость решений.

---

## Заключение

Модуль **FieldsList** представляет собой специализированное решение для управления списками полей в системе. Его основная цель – предоставить удобный механизм конфигурирования и отображения связанных полей, обеспечивая тем самым возможность эффективной настройки и расширения функциональности приложений на платформе NodeCMS.

# Документация модуля ForeignKeys

## Описание модуля

Модуль **ForeignKeys** предназначен для управления внешними ключами в системе. Он обеспечивает создание связей между справочниками и ключами, позволяя эффективно управлять ссылочной целостностью данных.

## Структура модулей

Модуль организован в соответствии с общей архитектурой проекта и включает следующие компоненты:

### Файловая структура

```
./services/ForeignKeys.service.js
```

### service.js

Основной сервисный слой модуля, содержащий всю бизнес-логику обработки внешних ключей.

## Сервисный класс

Класс `ForeignKeysService` наследуется от базового класса `DefaultMetaObject`, предоставляющего общие методы и свойства для всех метаданных компонентов.

### Конструктор

Конструктор инициализирует базовые параметры компонента:
- `id`: уникальный идентификатор компонента `"0f158d38-debf-4c6d-9a3a-836f20b0e22d"`
- `component`: название компонента `"ForeignKeys"`

### Метод form()

Метод возвращает конфигурацию формы для создания и редактирования внешних ключей. Форма состоит из трех полей:

1. **key**: Ключ-приемник
   - Тип поля: REF (ссылочный тип)
   - Связан с сервисом: `KeysService`
   
2. **guide**: Справочник-источник
   - Тип поля: REF
   - Не использует родительский справочник (`useParent: false`)
   - Связан с сервисом: `InfoserviceServiceGuide`
   
3. **guideKey**: Ключ источника
   - Тип поля: REF
   - Родительское поле: guide
   - Связан с сервисом: `KeysGuidService`

## Интеграция с другими компонентами

Модуль интегрируется с несколькими ключевыми сервисами:
- `KeysService`: управляет основными ключами
- `InfoserviceServiceGuide`: управляет справочниками
- `KeysGuidService`: управляет ключами справочников

Эти сервисы используются для формирования ссылок в полях конфигурации формы.

## Использование

Сервис `ForeignKeysService` должен использоваться в контроллерах и других сервисах, где требуется управление связями между справочниками и ключами. Пример использования:

```javascript
const foreignKeysService = new ForeignKeysService();
const configForm = await foreignKeysService.form();
console.log(configForm); // выведет конфигурацию формы
```

## Особенности реализации

Важной особенностью реализации является использование ссылки на классы сервисов через свойство `class` в конфигурации формы. Это позволяет динамически получать информацию о связанных сущностях и обеспечивать правильное отображение зависимых полей.

---

Данный модуль является важным компонентом системы управления метаданными, обеспечивая гибкое и масштабируемое решение для организации внешних ключей и связей между справочниками.

## Сервисный слой

Сервисный класс `InfoserviceService` реализует основные операции CRUD (Create, Read, Update, Delete):

```javascript
constructor() {
    super(__dirname); // Вызывает конструктор родительского класса
    
    this.id = 'b44b4843-f919-4362-b95c-4c354b2505bd'; // Уникальный идентификатор компонента
```

### Метод `form`

Метод возвращает форму конфигурации для создания нового элемента инфосервиса:

```javascript
async form(id) {
    const result = {
        form: [

                name: 'table',

                template: 'test_table',
            },
            {
                name: 'sqlalias',
                description: 'Сложный запрос',

                name: 'onoff',
```

### Метод `update`

Обновляет существующий элемент инфосервиса:


### Метод `delete`

Удаляет элемент инфосервиса:

```javascript

}
```

# Документация для модуля Keys

Модуль **Keys** предназначен для управления ключами объектов в системе. Данный модуль расширяет функциональность базового класса `DefaultMetaObject` из пакета `metadata-cmp`. Основная цель модуля - предоставление интерфейса для настройки первичных ключей объектов через форму конфигурации.

Модуль имеет следующую внутреннюю структуру:

```
./keys/
├── services/

└── package.json
```

---

## Ключевые компоненты

### 1. Класс KeysService

Класс `KeysService` наследуется от `DefaultMetaObject` и переопределяет метод `form()` для предоставления специфической формы конфигурации ключа.

#### Конструктор

Конструктор устанавливает уникальные идентификаторы компонента:

```javascript
this.id = '7827a8a5-4f92-443a-bb73-1dfcca358abf'; // Уникальный ID компонента
this.component = 'Keys'; // Имя компонента
```

#### Метод form()

Метод возвращает конфигурационную форму для настроек ключа:

```javascript
async form() {

        form: [

                name: 'primarykey',
                description: 'Первичный ключ',
                type: 'BOOL',

            // Дополнительные поля могут быть включены при необходимости

```

* Поля формы:
  - `name`: имя параметра ("primarykey")

- Уникальность значения
- Автоматическая генерация значения

Эти изменения должны вноситься в метод `form()` путем добавления новых объектов в массив формы.

---

## Примечания

Важно отметить, что текущий вариант реализации предполагает работу с булевыми значениями для свойств ключа. Это ограничение может быть снято путем модификации типа данных в форме и соответствующего обновления логики обработки этих данных в родительском классе `DefaultMetaObject`.

---

## Заключение

Модуль **Keys** представляет собой специализированную компоненту для управления ключевыми полями объектов в системе. Его гибкая структура позволяет легко адаптироваться под конкретные требования проектов благодаря наследованию базовых классов и настраиваемой форме конфигурации.
