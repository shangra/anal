# Модуль Loggers

Модуль **Loggers** предназначен для обработки и построения логов различных событий в системе. Основная цель модуля – сбор и подготовка данных для последующей отправки в систему логирования. Логгер собирает информацию о запросах, сессиях пользователей, заголовках HTTP-запросов и ответов, а также дополнительную метадату о виджетах, темах и ассистентах.

---

## Структура модуля

Модуль состоит из одного класса `LoggersService`, наследуемого от базового класса `Extensions`. Класс содержит два основных метода:

1. `resHeaderParse(headers)` - метод для парсинга заголовков HTTP-ответа
2. `buildLog(typeMessage, req, res, sessionStorage, responseData, context)` - основной метод для формирования лог-сообщений

---

## Метод resHeaderParse(headers)

Метод принимает строку с заголовками HTTP-ответа и возвращает объект с распарсенными значениями.

### Параметры:
- `headers`: строка с заголовками формата `"ключ: значение\nключ: значение"`

### Возвращаемое значение:
Объект вида `{ ключ: значение }`, где каждый ключ соответствует названию заголовка, а значение - его содержанию.

---

## Метод buildLog()

Основной метод для сборки лог-сообщения. Формирует подробное лог-событие на основе переданных параметров.

### Параметры:
- `typeMessage`: тип сообщения (строка)
- `req`: объект запроса Express
- `res`: объект ответа Express
- `sessionStorage`: хранилище сессии пользователя
- `responseData`: тело ответа сервера
- `context`: дополнительный контекст (обычно содержит трассировочный ID)

### Что делает метод:
1. Парсит заголовки ответа
2. Собирает информацию о текущем пользователе
3. Анализирует виджеты в сессии пользователя
4. Подсчитывает количество тем и ассистентов
5. Кодирует ответ в base64 (если возможно)
6. Формирует итоговый объект с полной информацией о событии

### Основные поля формируемого лог-сообщения:
- Метадата запроса (метод, URL, параметры, куки, заголовки)
- Информация о пользователе (ID, имя, статус, роли)
- Сведения о виджетах и темах
- Детали ответа сервера (код статуса, заголовки, тело)
- Дополнительный контекст (traceId)

---

## Особенности реализации

1. Использует механизм расширения через класс `Extensions` для возможного добавления кастомных хуков
2. Поддерживает работу с разными типами ответов (JSON и TEXT)
3. Предоставляет подробную информацию о состоянии сессии пользователя
4. Автоматически подсчитывает статистику по виджетам, темам и ассистентам

---

## Использование

Модуль предназначен для интеграции в систему логирования. Его основная функция - формирование унифицированных лог-сообщений, содержащих всю необходимую информацию для аналитики и мониторинга работы приложения.

Типичный сценарий использования:
1. Вызов метода `buildLog()` при каждом важном событии в приложении
2. Отправка сформированного лог-сообщения в централизованную систему логирования
3. Анализ собранных данных для диагностики проблем, мониторинга производительности и аудита действий пользователей
