# Документация для модуля Fields

## Обзор модуля

Модуль **Fields** предназначен для управления полями метаданных в системе. Модуль наследуется от класса `DefaultMetaObject` и расширяет его функциональность специфичными методами и свойствами для работы с полями.

## Структура модулей

### Папки и файлы

- `services/Fields.service.js`: Основной сервис модуля, содержащий всю основную логику обработки полей.

### Зависимости

Модуль зависит от следующих компонентов:

- `DefaultMetaObject.service`: Базовый класс для работы с объектами метаданных.
- `constants`: Константы конфигурации модуля.
- `InfoserviceGuide.service`: Сервис справочника информационных услуг, необходимый для настройки ссылок на справочники.

## Основные компоненты

### Класс FieldsService

Класс `FieldsService` реализует основные методы для работы с полями метаданных.

#### Конструктор

Конструктор инициализирует базовые свойства класса:

- `super(__dirname);`: Вызывает конструктор базового класса `DefaultMetaObject`.
- `this.id`: Устанавливает уникальный идентификатор компонента.
- `this.component`: Определяет компонент, связанный с этим модулем.

#### Метод form()

Метод возвращает конфигурацию формы для создания и редактирования полей метаданных. Форма включает следующие элементы:

1. Имя поля в СУБД (`nameField`)
   - Тип: STRING
   - Шаблон значения: test_field

2. Тип поля (`type`)
   - Тип: LIST
   - Возможные значения: UUID, TEXT, STRING, INTEGER, FLOAT, DATE, DATETIME, BOOLEAN, REF

3. Длина поля (`length`)
   - Тип: INTEGER
   - Шаблон значения: 255

4. Виртуальное поле (`virtual`)
   - Тип: BOOL

5. Значение виртуального поля (`fnfield`)
   - Тип: TEXT
   - Шаблон значения: CONCAT("field2", "field2")

6. Ссылка (`ref`)
   - Тип: REF
   - Использовать родительский элемент: Нет
   - Связан с сервисом справочника информационных услуг

7. Отключение поля (`onoff`)
   - Тип: BOOL

## Использование модуля

Для использования модуля необходимо создать экземпляр класса `FieldsService` и вызвать метод `form()` для получения конфигурации формы:

```javascript
const FieldsService = require('path/to/Fields.service');
const fieldsService = new FieldsService();
const formConfig = fieldsService.form();
console.log(formConfig);
```

## Интеграция с системой

Модуль интегрируется в систему через стандартный механизм загрузки сервисов. Для интеграции необходимо добавить модуль в соответствующую точку входа системы и настроить зависимости в файле `package.json`.

## Тестирование

Тестирование модуля должно включать проверку правильности возврата конфигурации формы методом `form()`. Рекомендуется проверить соответствие типов и настроек каждого элемента формы спецификации.

---

Данная документация описывает основной функционал модуля **Fields**, его внутреннюю структуру и способы взаимодействия с другими компонентами системы.

# Документация для модуля FieldsList

## Обзор модуля

Модуль **FieldsList** предназначен для управления списком полей в системе. Этот модуль расширяет функциональность базового класса `DefaultMetaObject`, предоставляя специфичные методы и настройки для работы со списком полей.

---

## Структура модуля

Модуль состоит из одного основного файла:

- `FieldsList.service.js`: Основной сервисный класс, содержащий всю логику работы со списком полей.

---

## Зависимости

Модуль зависит от следующих компонентов:

- `DefaultMetaObject.service`: Базовый класс метаданных объектов
- `Fields.service`: Сервис для работы с отдельными полями
- `constants`: Константы конфигурации модуля

Эти зависимости импортируются в начале файла:

```javascript
const DefaultMetaObject = require('../../metadata-cmp/services/DefaultMetaObject.service');
const FieldsService = require('./Fields.service');
const constants = require('../constants');
```

---

## Класс FieldsListService

Класс `FieldsListService` наследуется от `DefaultMetaObject` и добавляет специфичную функциональность для списка полей.

### Конструктор

Конструктор инициализирует базовые свойства класса:

```javascript
constructor() {
    super(__dirname);
    
    const name = 'FieldsList';
    
    this.id = constants[name].id; // Уникальный идентификатор компонента
    this.component = constants[name].component; // Компонент интерфейса
}
```

### Метод form()

Метод возвращает конфигурацию формы для редактирования элемента списка полей:

```javascript
async form() {
    return {
        form: [
            {
                name: 'ref',
                description: 'Поле',
                type: 'REF',
                link: new FieldsService().id, // Ссылка на сервис полей
                class: FieldsService, // Класс сервиса полей
            },
        ],
    };
}
```

Этот метод формирует форму с одним полем типа REF (ссылочное поле):
- Имя поля: `ref`
- Описание: `Поле`
- Тип: `REF` (ссылочный тип)
- Связь: указывает на уникальный идентификатор сервиса полей
- Класс: указывает на класс сервиса полей

---

## Использование модуля

Модуль предназначен для интеграции в систему через стандартный механизм загрузки сервисов. Для использования функционала модуля достаточно создать экземпляр класса `FieldsListService`:

```javascript
const fieldsListService = new FieldsListService();
```

Затем можно вызывать методы экземпляра для взаимодействия со списком полей.

---

## Интеграция с системой

Модуль интегрируется в общую архитектуру системы как часть подсистемы управления метаданными. Через наследование от `DefaultMetaObject` получает доступ ко всему необходимому функционалу базовой платформы.

---

## Тестирование

Тестирование модуля должно включать проверку правильности формирования конфигурации формы методом `form()` и проверки базовых свойств, установленных конструктором.

---

## Заключение

Модуль **FieldsList** представляет собой специализированный компонент для управления списком полей в системе. Его основная функция - предоставление правильной конфигурации формы для редактирования ссылок на поля, что достигается путем расширения функциональности базового класса метаданных объектов.

# Документация для модуля Indexes

## Описание модуля

Модуль **Indexes** предназначен для управления индексами в системе. Данный модуль наследуется от класса `DefaultMetaObject`, предоставляющего базовую функциональность для метаданных объектов. Модуль реализует специфическую логику для работы с индексами, используя предопределенные константы.

---

## Структура модуля

### Файл services/Indexes.service.js

Данный файл содержит основную реализацию сервиса для работы с индексами. Сервис расширяет класс `DefaultMetaObject` и добавляет дополнительную информацию об индексе.

#### Ключевые свойства:

- `id`: Уникальный идентификатор индекса, получаемый из предопределенных констант.
- `component`: Компонент, связанный с этим индексом, также извлекается из констант.

---

## Использование модуля

### Подключение модуля

Подключить сервис индексов можно следующим образом:

```javascript
const IndexesService = require('./services/Indexes.service');
const indexesService = new IndexesService();
```

### Основные методы

Поскольку данный сервис наследуется от `DefaultMetaObject`, он автоматически получает базовые методы для работы с объектами метаданных. Однако, конкретные реализации методов для работы с индексами не описаны в текущем файле и должны быть реализованы отдельно.

---

## Интеграция с системой

Модуль **Indexes** интегрируется в систему через стандартный механизм загрузки сервисов, предоставляемый платформой. Для интеграции нового функционала рекомендуется следовать следующей архитектуре:

1. Создайте необходимые роуты в директории `/routers`.
2. Реализуйте контроллеры в директории `/controllers`, обеспечивающие взаимодействие с API.
3. Добавьте тесты в директорию `__tests__/tests` для проверки функциональности сервиса.

---

## Пример использования

Предположим, вы хотите получить информацию об индексе:

```javascript
const indexesService = new IndexesService();
console.log(indexesService.id); // Выведет уникальный идентификатор индекса
console.log(indexesService.component); // Выведет компонент, связанный с индексом
```

---

## Заключение

Модуль **Indexes** обеспечивает базовый уровень абстракции для работы с индексами в системе. Используя наследование от `DefaultMetaObject`, он упрощает разработку и поддержку функциональности, связанной с управлением индексами. Для расширения функциональности рекомендуется добавлять дополнительные методы непосредственно в классе `IndexesService`.

# Документация для модуля InfoserviceGuide

## Описание модуля

Модуль **InfoserviceGuide** предназначен для управления метаданными информационных сервисов. Он включает в себя функциональность для создания, чтения, обновления и удаления метаданных, а также проверки валидности настроек перед сохранением изменений. Модуль наследуется от класса `DefaultMetaObject`, предоставляя базовую инфраструктуру для работы с метаданными.

---

## Структура модуля

### Класс `InfoserviceGuideService`

Класс реализует основные методы CRUD (Create, Read, Update, Delete) для работы с информационными сервисами, а также дополнительные методы для формирования формы настройки и проверки валидности параметров.

#### Методы класса

##### `form(id)`
Метод возвращает конфигурацию формы для ввода метаданных информационного сервиса. Форма состоит из набора полей различных типов:

- Имя таблицы (`table`)
- Сложный SQL-запрос (`sqlalias`)
- Фильтр (`filter`)
- Иерархия (`hierarchy`)
- Поле родителя иерархии (`fieldhierarchy`)
- Значение по умолчанию поля родителя иерархии (`fieldhierarchydefault`)
- Коннектор (`connector`)
- Переключатель отключения (`onoff`)

Возвращаемое значение:
```javascript
{
    form: Array<Object>
}
```

##### `validate(body)`
Метод проверяет валидность настроек перед созданием или обновлением метаданных. Проверяется соответствие следующих условий:

- Поле родителя иерархии (`fieldhierarchy`) не должно совпадать с полем представления (`fieldview`) первичного ключа информационной службы.

Возвращаемые значения:
- Массив ошибок (`Array<String>`), если обнаружены проблемы
- Пустой массив, если все параметры валидны

##### `create(body)`
Метод создает новый информационный сервис на основе переданного тела запроса. Реализация метода выводит информацию в консоль для целей отладки.

Параметры:
- `body`: тело запроса с настройками нового информационного сервиса

##### `read(id, options = {})`
Метод читает метаданные существующего информационного сервиса по указанному ID.

Параметры:
- `id`: уникальный идентификатор информационного сервиса
- `options`: необязательные опции чтения

Возвращаемое значение:
- Экземпляр класса `InfoServiceMetadata` с загруженными метаданными

##### `update(id, body)`
Метод обновляет существующие метаданные информационного сервиса.

Параметры:
- `id`: уникальный идентификатор информационного сервиса
- `body`: новое состояние метаданных

Реализация метода выводит информацию в консоль для целей отладки.

##### `delete(id)`
Метод удаляет информационные сервисы по уникальному идентификатору.

Параметры:
- `id`: уникальный идентификатор информационного сервиса

Реализация метода выводит информацию в консоль для целей отладки.

Для интеграции модуля в систему необходимо следовать стандартной архитектуре проекта, описанной в документации. Основные шаги включают:

1. Метод `validate()` обеспечивает важную проверку целостности данных, предотвращающую некорректную конфигурацию иерархических связей.

# Документация модуля Keys

## Описание модуля

Модуль **Keys** предназначен для управления настройками полей ключей информационных сервисов. Ключи определяют первичные поля идентификации записей в сервисах и настройки отображения этих записей.

## Структура модуля

Модуль состоит из одного класса `KeysService`, расширяющего функциональность базового класса `DefaultMetaObject`. Класс реализует специфическую логику формирования формы настроек и проверки валидности введенных данных.

## Основные компоненты

### Методы класса KeysService

#### Конструктор

Конструктор инициализирует базовые параметры модуля:
- `name`: Имя компонента ("Keys")
- `id`: Уникальный идентификатор компонента
- `component`: Компонент метаданных

---

### Метод form()

Метод возвращает конфигурацию формы настроек ключа информационного сервиса:

```javascript
async form() {
    return {
        form: [
            {
                name: 'primarykey',
                description: 'Первичный ключ',
                type: 'BOOL',
            },
            {
                name: 'fieldview',
                description: 'Поле представления',
                type: 'REF',
                link: new FieldsService().id,
                class: FieldsService,
            },
            {
                name: 'templateview',
                description: 'Шаблон представления',
                type: 'STRING',
                template: '[[field1]] ([[field2]] - [[field3]])',
            },
        ],
    };
}
```

Возвращаемое значение представляет массив объектов, каждый из которых описывает отдельное поле формы:
- `name`: имя поля
- `description`: описание поля
- `type`: тип данных поля
- `link`: ссылка на связанный компонент (если применимо)
- `class`: класс связанного компонента
- `template`: шаблон значения (опционально)

---

### Метод validate()

Метод проверяет валидность переданных настроек ключа:

```javascript
async validate(body) {
    const errors = [];
    
    // Проверка конфликта между полем представления и полем родительской иерархии
    const parent = await Metadata.getMetadata(owner_id);
    
    if (parent && typeof parent.manifest?.settings?.fieldhierarchy !== 'undefined') {
        const fieldhierarchy = parent.manifest.settings.fieldhierarchy;
        
        const fieldhierarchyValue = typeof fieldhierarchy === 'object' ? fieldhierarchy.value : fieldhierarchy;
        const fieldviewValue = typeof settings.fieldview === 'object' ? settings.fieldview.value : settings.fieldview;
        
        if (fieldhierarchyValue === fieldviewValue) {
            errors.push("'Поле представления' не может быть равно 'Полю родителя иерархии' инфосервиса.");
        }
    }
    
    return errors;
}
```

Логика метода:
1. Получает метаданные родительского компонента
2. Проверяет наличие настроек иерархии полей
3. Сравнивает выбранное поле представления с полем родительской иерархии
4. Возвращает массив ошибок, если обнаружены конфликты

---

## Использование модуля

Модуль должен использоваться в составе информационной системы для конфигурации ключевых полей компонентов. Типичное использование включает:

1. Формирование интерфейса настройки через метод `.form()` для предоставления пользователям возможности конфигурировать ключевые поля.
2. Валидацию пользовательских настроек перед сохранением через метод `.validate()`.

## Интеграция с другими компонентами

Модуль интегрируется с:
- `FieldsService`: для ссылки на поля компонентов
- `MetadataClass`: для доступа к метаданным компонентов
- Базовым классом `DefaultMetaObject`: для наследования базовой функциональности

## Примечания

Особенностью реализации является проверка уникальности выбора поля представления относительно поля родительской иерархии, что предотвращает потенциальные ошибки в структуре данных информационных сервисов.
