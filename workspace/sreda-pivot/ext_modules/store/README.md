# Документация для модуля Store

Модуль **Store** предназначен для управления хранилищем данных пользователей. Он обеспечивает возможность сохранять, получать и обновлять индивидуальные настройки и информацию каждого пользователя через взаимодействие с базой данных и сессией текущего пользователя.

---

## Структура Модуля

Модуль состоит из следующих компонентов:

- **StoreService**: Основной сервис, предоставляющий методы для взаимодействия с хранилищем данных.
- **StoreModel**: Модель данных, отвечающая за работу с базой данных.
- **httpContext**: Сервис для доступа к текущему состоянию HTTP-сессии пользователя.

---

## Методы StoreService

### 1. setData(key, value)
Записывает значение в хранилище данных пользователя.

#### Параметры:
- **key:** Уникальный ключ для хранения значения.
- **value:** Значение, которое нужно сохранить.

#### Возвращаемое значение:
Объект `{ result: boolean }`, где результат указывает успешность операции.

---

### 2. getData(key)
Возвращает значение по указанному ключу из хранилища данных пользователя.

#### Параметр:
- **key:** Ключ, по которому запрашивается значение.

#### Возвращаемое значение:
Объект формата `{ result: boolean, value: any }`, содержащий результат операции и само значение.

---

### 3. getAllData()
Возвращает все сохраненные данные пользователя из хранилища.

#### Возвращаемое значение:
Объект формата `{ result: boolean, value: object }`, содержащий результат операции и словарь всех хранимых пар ключ-значение.

---

### 4. getUserDataByKey(key)
Проверяет наличие ключа в хранилище и возвращает соответствующее значение либо из базы данных, либо из сессии пользователя.

#### Параметр:
- **key:** Запрашиваемый ключ.

#### Возвращаемое значение:
Объект формата `{ result: boolean, data: any }`, содержащий результат проверки наличия ключа и его значение.

---

### 5. setUserDataByKey(key, value)
Устанавливает новое значение для указанного ключа в базе данных и сохраняет его в сессии пользователя.

#### Параметры:
- **key:** Ключевое имя параметра.
- **value:** Новое значение.

#### Возвращаемое значение:
Объект формата `{ result: boolean }`, указывающий успешность сохранения.

---

### 6. getAllUserData()
Возвращает полную коллекцию данных пользователя, объединяя данные из хранилища и сессии.

#### Возвращаемое значение:
Объект формата `{ result: boolean, ...object }`, содержащий флаг результата и объединение всех текущих данных пользователя.

---

### 7. saveInSession(data)
Сохраняет переданный объект данных в текущем состоянии сессии пользователя.

#### Параметр:
- **data:** Объект данных для сохранения в сессии.

---

### 8. getAllValuesByKey(key, createdUser=undefined)
Возвращает массив всех значений по заданному ключу, возможно фильтруя по автору создания записей.

#### Параметры:
- **key:** Имя ключа.
- **createdUser:** Необязательный параметр фильтра по ID создателя данных.

#### Возвращаемое значение:
Объект формата `{ result: boolean, value: array }`, содержащий результат и массив найденных значений.

---

## Использование модуля

Модуль **Store** рекомендуется применять везде, где требуется индивидуальное хранение настроек и данных пользователей. Например, для реализации персонализации интерфейса, хранения предпочтений пользователя или временных параметров сеанса.

Использование методов сервиса предполагает предварительную проверку аутентификации пользователя и доступность сессии. Все операции выполняются асинхронно, поэтому важно учитывать использование промисов и обработки ошибок.

---

## Пример использования

```javascript
const storeService = new StoreService();

async function updateUserSettings(settings) {
    const key = 'user_settings';
    
    // Сохранить настройки пользователя
    await storeService.setUserDataByKey(key, settings);
    
    // Получить актуальные настройки пользователя
    const currentSettings = await storeService.getUserDataByKey(key);
    
    console.log(currentSettings.data); // выведет актуальную настройку пользователя
}
```

Таким образом, модуль **Store** представляет удобный интерфейс для централизованного управления персональными данными пользователей в приложении.
