# SREDA Analytic

Коробка аналитики: **pivot** (бэкенд), **админка** и **аналитика** (два фронта).

- **Windows:** всё поднимается из корня одной командой `npm start`.
- **macOS:** после установки и миграций запускайте **три процесса отдельно** — pivot и два фронта, в трёх окнах Terminal. Команду `npm start` из корня на Mac не используйте.

Нужны Node.js 18+, PostgreSQL и лицензионный ключ. Пользователю БД нужны права `CREATE` (коробка создаёт схему).

Все пути ниже — от корня проекта (там лежат `package.json` и `.env.example`).

---

## 1. Один раз: окружение, установка, база

Это одинаково на Windows и на Mac. Делается **из корня**, не из папок модулей.

### 1.1. Файл `.env`

В Terminal / Git Bash:

```bash
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` в редакторе и заполните **без пробелов вокруг `=`**:

```
DB_HOST=
DB_PORT=5432
DB_USER=
DB_PASS=
DB_DATABASE=
DB_SCHEMA=pivot
LICENSE_KEY=
```

`DB_SCHEMA` — имя **новой** схемы, которой ещё нет в базе.

Если ключа нет в файле, его спросят при `npm run db`. Без ключа сервисы не стартуют.

`DB_SSL` обычно не нужен: для удалённого хоста TLS включается сам, для `localhost` — нет. Если облачная БД проброшена туннелем на `127.0.0.1`, добавьте:

```
DB_SSL=require
DB_SSL_REJECT_UNAUTHORIZED=false
```

### 1.2. Зависимости

Из **корня**:

```bash
npm install
```

Дождитесь конца без красных ошибок. Это ставит пакеты коробки и модулей. Фронты ставятся с `--legacy-peer-deps` сами. Lock-файлы не удаляйте.

Если фронт потом орёт про `ajv` или `ERESOLVE`, зайдите в его папку и выполните:

```bash
npm install --legacy-peer-deps --ignore-scripts
```

Потом вернитесь к шагам запуска.

### 1.3. Схема в Postgres

Из **корня**:

```bash
npm run db
```

Команда:

- разложит корневой `.env` в модули;
- создаст схему и накатит миграции;
- спросит лицензионный ключ, если его ещё нет;
- спросит, создавать ли тестовый куб (`да` / `нет`).

Повторно `npm run db` схему с нуля не ломает: если платформа уже есть, миграции пропускаются, ключ и куб можно пройти снова.

## 2. Windows: запуск из корня

Из корня:

```bash
npm start
```

Появятся:

| Сервис | Адрес |
| --- | --- |
| Pivot | http://127.0.0.1:3391 |
| Аналитика | http://127.0.0.1:3380 |
| Админка | http://127.0.0.1:3372 |

Логин: `su` / `su`. Остановка: Ctrl+C в том же окне.

Только pivot: `npm start -- --only pivot`.

## 3. macOS: три окна, три запуска

На Mac **не** делайте `npm start` из корня. Сначала шаги 1.1–1.3. Потом три окна Terminal. Окна **не закрывать** — закрыли окно, процесс умер.

Порядок обязательный: **сначала pivot**, дождитесь что он живой, **потом** два фронта.

### Окно 1 — pivot

```bash
cd путь/к/SREDA.Analytic/workspace/sreda-pivot
node server.js
```

Именно `node server.js`, не `npm start` и не `npm run dev` (там collect и nodemon, в коробке так не запускаем).

Ждите в логе что-то вроде `Http server started on port: 3391` и сообщений лицензии (`Лицензия активна`). Если пишет `LICENSE_KEY не найден` / подпись неверна / проблемы с лицензией — процесс сам выйдет. Пока это окно красное или сразу закрылось, фронты не запускайте.

Порт берётся из `workspace/sreda-pivot/.env` (его пишет `npm run env` / `npm run db`). Если порта нет — из корня ещё раз `npm run env`.

Это окно оставляете работать.

### Окно 2 — админка

Новое окно Terminal:

```bash
cd путь/к/SREDA.Analytic/workspace/frontend-adm
npm start
```

Должно подняться на http://127.0.0.1:3372 (`PORT` уже в `.env` модуля). Это окно тоже не закрывать.

### Окно 3 — аналитика

Ещё одно окно:

```bash
cd путь/к/SREDA.Analytic/workspace/sreda-analytics-spreadsheet-frontend
npm start
```

Должно подняться на http://127.0.0.1:3380. Окно не закрывать.

### Проверка

В браузере:

1. http://127.0.0.1:3391 — pivot отвечает.
2. http://127.0.0.1:3380 — аналитика.
3. http://127.0.0.1:3372 — админка.

Логин: `su` / `su`.

Остановка на Mac: в каждом из трёх окон Ctrl+C. Сначала фронты, потом pivot.

Если перезапускаете только UI — pivot в первом окне можно не трогать.

## Команды из корня

| Команда | Когда |
| --- | --- |
| `npm install` | первый раз и после смены зависимостей |
| `npm run env` | только разложить `.env` по модулям |
| `npm run db` | миграции, ключ, тестовый куб |
| `npm start` | **только Windows** — все сервисы вместе |
| `npm run list` | состав коробки |
| `npm run validate` | проверить пути |

Состав модулей — `box.config.json`.

## Если не стартует

- **Нет ключа / неверная подпись / «проблемы с лицензией»** — `LICENSE_KEY` в корневом `.env`. Коробка копирует его в pivot. Ключ привязан к этой базе; перенос схемы на другой кластер = новая активация.
- **Фронт и `ajv` / `ERESOLVE`** — в папке этого фронта `npm install --legacy-peer-deps --ignore-scripts`. Lock-файлы не удалять.
- **Логин 500, `no encryption`** — TLS, см. шаг 1.1.
- **На Mac фронт есть, данных нет** — pivot в первом окне не запущен или упал (лицензия, БД).
- Логи при запуске из корня (Windows): папка `logs/`. На Mac смотрите вывод в трёх окнах Terminal.
